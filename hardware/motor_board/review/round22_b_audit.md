## Notes (no action required)

- **N1 — CLL during a resume (:675, :606).** Step 2 sets BKE = 0 on TIM8 and step 4 sets it back to 1.  The window includes the "wait until it is slow" branch, which is unbounded.  For that whole window a core lockup no longer breaks TIM8, although the watchdog row says "CLL needs BKE = 1 on every timer it should stop".  The chip stays coasted until step 3, and the IWDG still resets within ~20 ms, so the exposure is small.  Still, consider doing the slow-wait before BKE = 0, or say that the gap is accepted.
- **N2 — "more than ~3 in a second → drive row 2" (:677).** It is unclear whether this means "latch that drive" (row 2's > 3/s clause) or "run row 2's action" (coast, rewrite, resume again).  The action would itself start another resume window, so "latch that drive" is presumably intended.  An OCP on *both* chips in one supply-restart resume is excluded from row 1 by the same sentence.  Say whether each chip counts separately.
- **N3 — §9 step 3 flow (:740–741).** After the switch-open tests moved to step 6, the step reads "…W_ARM_S falls; (The switch-open tests … end of step 6.)  Then: W_ARM rises…".  It is readable but has a dangling semicolon and "Then:".
